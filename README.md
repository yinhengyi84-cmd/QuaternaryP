# 魔道祖师 网页地图

首版包含 190 个真实行政地块与 172 条地理志记录，支持电脑、手机浏览器。React + TypeScript + Vite 构建，SVG + D3 绘制真实地图；无须在线地图账号或地图密钥。

## 启动

在此目录双击 `启动地图.cmd`，然后在浏览器打开屏幕显示的电脑地址，通常是 `http://localhost:5173/`。首次进入开局选角色页，选择或抽取角色后进入玩家主页面。项目已附带构建好的网页，普通使用无需重新安装依赖或联网。

手机与电脑连接同一 Wi-Fi 后，打开启动窗口中的手机地址。保持启动窗口打开；按 Ctrl+C 停止服务。需要 Node.js 22.12 或更高版本，推荐 Node.js 24 LTS。

也可以在此目录打开终端执行：

```text
npm start
```

若手机无法连接，检查电脑与手机是否同一局域网，以及电脑防火墙是否允许该本地服务。请使用启动窗口中的实际地址，不使用手机自身的 localhost。开发修改时先运行 `npm ci`，再运行 `npm run dev`。

## 操作

- 鼠标拖动平移，滚轮缩放；手机使用单指拖动、双指缩放。
- 点击行省查看归属、中文名、现实原型、地理和剧情资料。
- 五角星表示六方首都，圆点表示战略城市；点击城市符号可打开其所属地块档案。地图拥挤时部分名称会暂时隐藏，放大后出现，城市符号始终保留。
- 搜索支持地块与城市中文名、欧洲名称及原表编号，如 `长沙`、`鹅城`、`Riga`、`D010`。结果可使用上下方向键和 Enter 选择，Ctrl+K 聚焦搜索。
- 左侧书本按钮打开全部地理志；六阵营图例可聚焦单一阵营，“全部”恢复显示。
- 十字准星按钮恢复全图。手机资料面板可通过右上角关闭按钮收起。
- 地图志顶栏的“玩家主页面”返回本人游玩页面；未选角色时先进入开局选角。玩家页顶部的“地图志”打开地图；手机端也保留完整文字。点击“地图来源”查看数据来源与许可。

## 两种开局原型

网站根地址默认进入 `/#/opening`，可进入 `/#/choose` 自主选择，或 `/#/draw` 随机抽取。自主选择会先展示六张塔罗档案，玩家阅读后确认；随机抽取在揭晓前不展示人物，揭晓后使用同一套塔罗图案与简介。两种路径都进入 `/#/play`，只显示本人的角色和行动。已有身份时，开局页显示“继续以某角色游玩”，不会重新选角。直接查看地图可使用 `/#/atlas`。

六人简述沿用 `../gemini-code-1782728297042.html` 对应原文；原文件的“曹文豪”统一为最终角色名“曹文浩”，另两位旧角色不进入此版本。塔罗图案是项目内 SVG，不依赖外网图片。人物的初始阵营徽记使用地图阵营配色，仅表示开局归属，不限制后续转换阵营。旧版简介涉及较晚剧情，正式开局时间线仍需由 DM 核对。

当前两种体验共用本浏览器会话中的一份试用身份；改用另一种方式会开启新的本地试用。“重新选择”“重新试抽”仅用于比较原型。不同设备可能选择或抽到同一人物，也没有真实座次、DM 审批或多人同步。未来的服务端字段、玩家请求和 DM 操作见 `开局角色分配接口预案.md`。

## Play 原型

Play 页面只呈现当前玩家的行动地点、行动输入、D20 条件、个人结果与剧情。它不显示其他玩家、阵营席位顺序或 DM 控制按钮。提交后，本地原型约 3 秒自动载入示例判定条件；点击投掷时会弹出聚焦动画，骰子旋转结束才揭晓骰点，随后可返回个人剧情。完成判定后保持等待状态。系统设置为减少动态效果时会缩短等待并跳过旋转。正式对局将由 DM 通过 CLI 审核与推进，服务端只向对应玩家发送其私有内容。

页面最下方的“我的八维”以分色八边形与精确数字显示本人角色四维和当前阵营四维，初值来自《剧情/人物八维.docx》。金色上半区为权力、魅力、智慧、信念，青绿色下半区为经济、军力、民生、科技。当前使用本地初值；后续可替换数据适配器接收服务端更新，详见 [八维数值接口预案](八维数值接口预案.md)。八维暂不参与 D20 演示计算。

本地角色只在当前浏览器会话显示，正式身份与顺序将在后续加入房间流程中确定。页面上的 DC、角色修正和情境修正是固定演示数值，骰点由当前浏览器临时生成；没有真实 DM 审核、AI 生成、房间、权限、存档或玩家间同步。玩家页与地图志往返会保留草稿、地点、地图展开状态、判定阶段和骰点，模拟审核计时也会继续；刷新或关闭网页、新开局会重置判定演示。正式多人版需要由服务端锁定判定条件、生成骰点并记录结果。

## 边界与资料

真实边界优先，地区数量与 Maps.png 的原始分块不完全相同。柏林、勃兰登堡、莫斯科市与莫斯科州等单独绘制；挪威的固定来源采用 2022 年合并郡。

`边界对应说明.md` 列出全部原表条目对应的真实地块。部分旧县与现代市镇的关联为暂定，页面会注明“对应待核”或“所属地区资料”。地图中的阵营为架空设定。

14 个城市标记存放在 `public/data/cities.json`，位置使用现实欧洲城市坐标。汉堡标作「宜宾」，科隆标作「鹅城」；明斯克州在网页中显示为「合肥·明斯克州」，来源 Word 的 S047 原文仍保留供核对。

`public/data/atlas.json` 保存文字、初始阵营及对应关系，`geometry.geojson` 保存真实地块，`water.geojson` 保存真实湖泊。所有数据随项目提供，地图浏览无需访问第三方服务。`boundary-manifest.json` 保存下载版本、出处、许可证及文件校验值。数据来源条款见 `DATA_LICENSES.md`。

## 检查与构建

```text
npm run check:data
npm test
npm run test:e2e
npm run build
npm run preview
```

浏览器测试默认使用本机 Microsoft Edge。构建结果位于 `dist`，可部署到普通静态服务器；首版未提供房间、归属修改、登录或数据库。

## 后续扩展

地块稳定 ID、初始阵营与地理志记录已分开。后续可增加独立的对局状态，通过 Node.js 接口与 WebSocket 同步当前归属，不必改写静态边界。当前浏览版不记录玩家操作。

当前地图没有可调用的领土变更 API；建议的接口、版本号和同步事件格式见 `领土变更接口预案.md`。

维护边界数据时，`scripts/download_boundaries.py` 与 `download_water.py` 下载原数据到 `.cache/boundaries`；保留元数据文件即可复用同一固定下载版本。`scripts/build_atlas.py` 校验原 Word 内容并生成网页数据。普通运行与构建不需要 Python或重新下载边界。
